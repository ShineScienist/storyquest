# StoryQuest 1.2.0 - Roadmap

> Историческая дорожная карта 1.2.0. Актуальные планы на 1.3.0 и 1.4.0 находятся
> в [ROADMAP.md](ROADMAP.md); упоминания 1.3.0 ниже считаются устаревшими.

> Статус: реализовано в 1.2.0. Экспорт и импорт доступны командами; кнопки в редакторе
> отложены. Смешанные личные и общие цепочки разрешены с предупреждением.

## Цель

1.2.0: условия и ветки квестов, общий прогресс для коопа (если нужен) и экспорт/импорт квестов в JSON.

Не входит в 1.2.0:

- новые типы целей;
- отдельный экран наград;
- ветвящиеся диалоги, они уходят в 1.3.0;
- полировка waypoint'ов и журнала, экран конфига, API и прочие пункты 8-9.

Награды через `completeCommands` уже работают: предметы, XP и команды можно выдавать оттуда. Отдельный красивый экран наград можно сделать позже.

## 1. Условия и ветки

### Данные квеста

Добавить в `Quest`:

- `requiredQuests: List<String>` - ID квестов, которые должны быть завершены.
- `requireAll: boolean` - `true`: нужны все квесты, `false`: достаточно любого. По умолчанию `true`.
- `hideUntilAvailable: boolean` - если `true`, квест не показывается в журнале, пока условия не выполнены. Если `false`, квест виден, но заблокирован. По умолчанию `false`.
- `branch: String` - имя ветки. Пустая строка означает, что квест не участвует в ветвлении. Квесты с одинаковым непустым значением взаимоисключающие.
- `scope: SOLO | SHARED` - личный или общий квест. По умолчанию `SOLO`. Нужен только если делаем кооп.

Старые квесты при загрузке получают значения по умолчанию: пустой список, `requireAll = true`, `hideUntilAvailable = false`, пустая ветка, `SOLO`. Миграция данных не нужна.

### Поведение

- Условия в 1.2.0 проверяются только по завершённым квестам. Флаги, стадии сюжета и условия по активным квестам откладываются до 1.3.0.
- `canStart(player, quest)` проверяет:
  - квест ещё не завершён и не активен;
  - все или хотя бы один `requiredQuests` завершены;
  - в той же ветке нет активного или завершённого квеста;
  - требование проверяется по прогрессу своего типа: общий квест - по общему прогрессу мира,
    личный - по прогрессу игрока. Смешанные цепочки разрешены, но редактор предупреждает.
- Ветка блокируется в момент старта. Игрок выбрал ветку и уже не может начать альтернативу. Сброс прогресса снимает блокировку.
- В одну ветку кладутся только квесты-развилки. Продолжения ветки в неё не добавляются, они просто требуют выбранный квест.
- Пример:
  - `choice` завершён;
  - открываются `guard_path` и `bandit_path`, у обоих `branch = "side"`;
  - игрок начал `guard_path`, после этого `bandit_path` заблокирован;
  - `guard_2` требует `guard_path`, но не имеет ветки, поэтому доступен после завершения `guard_path`.
- После завершения квеста пересчитать доступные квесты и запустить `autoStart`-квесты, у которых условия стали выполнены. Защита от бесконечного цикла: не больше 100 стартов за один пересчёт.
- `autoStart` проверяет условия, а не только вход игрока в игру.
- Если два `autoStart`-квеста находятся в одной ветке, это конфликт: предупредить в редакторе.
- Команда `/storyquest start` проверяет условия. Для администраторов добавлена `force-start`, чтобы обойти проверку при тестировании.
- Если квест скрыт, но является требованием для видимого квеста, в журнале показывать "???" вместо названия, чтобы не спойлерить.

### Редактор

- В `QuestFormScreen` добавить кнопку "Условия...".
- Отдельный экран `QuestConditionsScreen`:
  - список требуемых квестов с кнопками добавления и удаления;
  - выбор квеста из списка с поиском по названию и ID;
  - переключатель "Все" / "Любой";
  - переключатель "Скрывать, пока не выполнены условия";
  - поле "Ветка" с подсказкой существующих веток;
  - предупреждения о циклах, отсутствующих квестах и конфликтах автостарта.
- В `QuestFormScreen` показывать краткую сводку: "После: ...", "Скрыт до выполнения", "Ветка: ...".

### Журнал

- Заблокированный квест показывать с замком и списком требований.
- Кнопка "Начать" неактивна, пока условия не выполнены.
- Если игрок выбрал другую ветку, показывать "Выбрана другая ветка".
- Выполненные требования отмечать галочкой.
- Скрытые квесты не отправлять клиенту, пока они не станут доступны, активны или завершены.

### Валидация

- Запретить квест, который требует сам себя.
- Не давать сохранить цикл: A требует B, B требует A. Отсутствующие квесты разрешать при авторской работе, но показывать предупреждение.
- Проверять пустые и дублирующиеся ID при импорте.
- Проверять конфликты `autoStart` в одной ветке.
- Предупреждать, если общий квест требует личный квест или наоборот, если это создаёт
  непонятную цепочку. Смешанные цепочки не запрещены: требование проверяется по типу
  своего квеста.

## 2. Кооп

Нужно выбрать одну модель. Ниже три варианта.

### Вариант A: общий прогресс мира

Один прогресс на весь мир/сервер. Подходит для одной компании на приватном сервере.

- У квеста галочка "Общий квест" (`scope = SHARED`).
- Один игрок начал квест, квест активен у всех онлайн-игроков.
- Любой игрок закрывает VISIT-цель. Для MANUAL-цели достаточно одной команды.
- Квест завершается для всех, уведомления и диалоги получают все онлайн-игроки.
- Новый игрок при входе видит текущее состояние общего квеста.
- Личные квесты остаются личными.
- Ветку выбирает первый, кто начал квест. Это групповое решение, его нельзя отменить без сброса.
- Команды старта и завершения по умолчанию выполняются для каждого онлайн-игрока, чтобы все получили награды и сообщения. Если нужно выполнить один раз, добавить галочку "Выполнять команды один раз".
- Для сброса общего прогресса добавить отдельную команду, например `/storyquest reset-shared <quest>`.
- Условия общего квеста проверяются по общему прогрессу. Не смешивать в одной цепочке личные и общие квесты без предупреждения.

Минус: если на одном сервере играют разные компании, они делят прогресс.

### Вариант B: пати

У каждой группы свой прогресс.

- Команды пати: создать, пригласить, принять, выйти, исключить, список.
- Лидер и участники, прогресс хранится на пати.
- Общие квесты активируются для пати, а не для всего мира.
- Нужна отдельная модель данных и синхронизация. Это заметно больше работы.
- Лучше делать в 1.3.0, если понадобится публичный сервер с несколькими группами.

### Вариант C: личный прогресс, общие цели

У каждого свой квест, но выполнение цели одним игроком засчитывается всем, у кого квест активен.

- Компромисс, но сложно объяснить игрокам.
- Позднее подключение и рассинхрон прогресса создают проблемы.
- Не рекомендую для 1.2.0.

### Решение

- 1.2.0: вариант A, общий прогресс мира.
- 1.3.0: вариант B, пати.

Для 1.2.0 считаем, что карта рассчитана на одну компанию на приватном сервере. Если появится публичный сервер с несколькими группами, пати будет в 1.3.0.

### Решения по коопу

- VISIT-цель общего квеста закрывает любой игрок.
- Команды старта и завершения выполняются для каждого онлайн-игрока.
- Галочка "выполнять команды один раз" добавляется как опция, если понадобится.
- Ветку выбирает первый, кто начал квест.
- Сброс общего прогресса делается отдельной командой.

## 3. Экспорт и импорт

### Формат

Использовать JSON, а не DAT.

- JSON читаемый, его можно сравнивать, править вручную, переводить и хранить в git.
- DAT - это внутренний NBT-файл мира. Оставляем его для автосохранения и автобэкапов.
- Для обмена и переноса между мирами использовать JSON.
- Прогресс игроков не экспортируется, только определения квестов.

Пример структуры:

```json
{
  "formatVersion": 1,
  "modVersion": "1.2.0",
  "quests": [
    {
      "id": "guard_path",
      "title": "Путь стражи",
      "requiredQuests": ["choice"],
      "requireAll": true,
      "hideUntilAvailable": false,
      "branch": "side",
      "scope": "solo",
      "objectives": []
    }
  ]
}
```

В JSON попадают все поля квеста: глава, описание, текст, флаги, команды, цели, маркеры, условия, ветка и `scope`.

### Файлы и команды

- Папка: `config/storyquest/quests/`.
- `/storyquest export [name]` - экспорт всех квестов. Без имени использовать дату и время.
- `/storyquest import <name> [merge|replace]` - импорт.
- Права: уровень оператора 2.
- Имя файла проверять: только буквы, цифры, `_` и `-`, без путей и `..`.
- Расширение `.json` добавлять автоматически.

### Импорт

- `merge` по умолчанию: квесты с тем же ID заменяются, новые добавляются, остальные остаются.
- `replace` только с подтверждением: `/storyquest import <name> replace confirm`.
- При `replace` очищать прогресс по квестам, которых нет в новом наборе, чтобы старый прогресс не вернулся при повторном импорте.
- Проверять ID, дубликаты, ссылки на несуществующие квесты, циклы, допустимые значения enum, цвета и координаты.
- Импорт атомарный: сначала разобрать и проверить всё, потом заменить данные. При ошибке ничего не менять.
- После импорта синхронизировать всех игроков и пересчитать условия и `autoStart`.

### Бэкапы

- Перед импортом и перед сохранением в редакторе делать резервную копию `storyquest_quests.dat`.
- Хранить последние 20 копий.
- При ошибке импорта показывать путь к бэкапу.
- Импорт DAT не делать в 1.2.0. При необходимости можно добавить восстановление из бэкапа позже.

### Редактор

- Команды - обязательный минимум.
- Кнопки "Экспорт" и "Импорт" в редакторе можно добавить, если останется время. Импорт через список файлов, без ручного ввода пути.

## 4. Что не делаем в 1.2.0

- Новые типы целей: kill, collect, craft, interact, timer.
- Отдельный экран наград. `completeCommands` достаточно.
- Ветвящиеся диалоги. Они в 1.3.0, но ветки квестов уже будут готовы к ним.
- Полировка waypoint'ов, несколько отслеживаемых квестов, прогресс-бар, архив, книга-предмет.
- Экран конфига, API, интеграции с картами и прочие пункты 8-9.

## 5. Тесты

- Цепочка A -> B: B не виден или заблокирован до завершения A.
- Ветка B/C: старт B блокирует C; сброс разблокирует.
- Скрытый и показанный заблокированный квест.
- `autoStart` после завершения квеста и при входе игрока.
- Цикл условий и отсутствующий квест.
- Кооп на двух клиентах: старт одним, завершение цели другим, позднее подключение, сброс.
- Экспорт -> импорт без потерь: все поля, включая условия, ветки, маркеры и `scope`.
- Импорт merge и replace, ошибки валидации, автобэкап.
- Чистый dedicated server.

## 6. Принятые решения

- Кооп: вариант A, общий прогресс мира. Вариант B, пати, в 1.3.0.
- Ветка блокируется при старте.
- Заблокированные квесты по умолчанию показываются с требованиями; галочка "скрывать" доступна.
- Импорт по умолчанию merge; replace только с подтверждением.
- Общий VISIT закрывает любой игрок.
- Команды общего квеста выполняются для каждого онлайн-игрока.
- Сброс общего прогресса - отдельная команда.
- Смешанные личные и общие цепочки разрешены с предупреждением; требование проверяется
  по прогрессу своего типа.
- JSON-импорт по умолчанию merge; replace требует `confirm`.
- Экспорт и импорт в 1.2.0 доступны командами, без кнопок в редакторе.
