# StoryQuest

[![Build](https://github.com/ShineScienist/storyquest/actions/workflows/build.yml/badge.svg)](https://github.com/ShineScienist/storyquest/actions/workflows/build.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Minecraft](https://img.shields.io/badge/Minecraft-1.21.1-62b47a.svg)](https://www.minecraft.net/)
[![NeoForge](https://img.shields.io/badge/NeoForge-21.1%2B-e04e14.svg)](https://neoforged.net/)

Квестовая система для **Minecraft 1.21.1 / NeoForge**, заточенная под сюжетные карты и приключения.
В отличие от FTB Quests здесь нет «дерева крафтов»: квесты — это главы истории, диалоги,
зоны и команды. Всё создаётся прямо в игре; JSON используется только для обмена,
переноса между мирами и ручного редактирования.

> **Статус:** стабильная версия **1.2.0** опубликована на
> [CurseForge](https://www.curseforge.com/minecraft/mc-mods/storyquest).
> Ветка `main` содержит разработку **1.3.0-beta.2** — темы Paper и Book.
> Скачивайте релизные jar со страницы проекта, а не из CI-артефактов.

## Что уже есть

- **Редактор квестов в игре** (клавиша `K`, нужны права оператора).
- **Журнал квестов** (клавиша `J`): главы, состояния, цели, описание.
- **Две темы интерфейса** — Paper (пергамент) и Book (кожаный переплёт). Тема
  переключается кнопкой в журнале или в настройках, без перезапуска игры.
- **HUD-трекер** активного квеста с настройкой угла, масштаба и прозрачности.
- **Диалоги** с рассказчиком и постраничным текстом (вступление и финал квеста).
- **Цели двух типов:**
  - `Вручную` — закрывается командой/скриптом;
  - `Посещение` — автоматически, когда игрок входит в сферу (измерение + X/Y/Z + радиус).
- **Метки и вейпоинты** для целей «Посещение»: галочка, булавка или звезда над точкой,
  столб света и HUD-компас с направлением и расстоянием.
- **Условия и ветки:** квесты могут требовать завершённые квесты (все или любой один),
  скрываться до выполнения условий и блокировать альтернативные ветки.
- **Общие квесты для коопа:** один прогресс на мир, старт и цели засчитываются всей группе.
- **Команды при старте и завершении квеста** — главный инструмент сюжетной карты.
- **Экспорт и импорт JSON:** перенос квестов между мирами, резервные копии и ручное редактирование.
- Личный прогресс каждого игрока сохраняется отдельно и **не сбрасывается после смерти**.
  Прогресс общих квестов хранится в мире.
- Квесты хранятся **в файле мира**, поэтому копируются вместе с картой.

## Установка и сборка

1. Установите JDK 21.
2. Соберите мод:

```bash
gradlew build
```

Готовый jar появится в `build/libs/storyquest-1.3.0-beta.2.jar`.

3. Положите его в `mods` клиента и/или сервера NeoForge 1.21.1.

Для запуска в dev-окружении: `gradlew runClient` / `gradlew runServer`.

### Разработка

- JDK 21 и Gradle wrapper из репозитория; отдельный Gradle устанавливать не нужно.
- `gradlew build` — сборка и проверка, `gradlew runClient` — клиент с модом.
- CI (GitHub Actions) собирает каждый push и pull request; jar доступен в артефактах сборки.
- Исходники интерфейсных текстур лежат локально у автора и в репозиторий не входят;
  готовые PNG лежат в `src/main/resources/assets/storyquest/textures/`.

## Быстрый старт

1. Зайдите в мир с включёнными читами (или на сервер с правами оператора).
2. Нажмите **`K`** — откроется редактор квестов.
3. Нажмите **«Новый»**, заполните вкладку **«Основное»**:
   - `ID` — короткое имя для команд (латиница, цифры и `_`, например `chapter_1_intro`);
   - название, глава, порядок;
   - описание (видно в журнале);
   - флаги (см. ниже).
4. Вкладка **«Текст»** — диалог при старте и финале. Страницы разделяются `|`.
5. Вкладка **«Цели»** — добавьте хотя бы одну цель.
6. **«Сохранить»**.
7. Выдайте квест командой:

```
/storyquest start quest_1
```

Квест появится в журнале (`J`) и в HUD-трекере.

### Об ID квеста

`ID` — это внутреннее имя квеста. Именно оно используется во всех командах:

```
/storyquest start chapter_1_intro @a
```

Правила: только `a-z`, `0-9` и `_`, до 64 символов. ID можно изменить позже —
при переименовании старый ID удаляется вместе с прогрессом игроков по нему
(сами квесты и остальные квесты не затрагиваются). Занятый ID сохранить нельзя.

## Флаги квеста

| Флаг | Что делает |
|------|------------|
| **Виден** | Квест показывается в журнале до старта. Если выключить — игрок увидит его только после выдачи. |
| **Можно принять** | Игрок может взять квест из журнала кнопкой «Принять». Иначе только командой. |
| **Автостарт** | Квест автоматически выдаётся при входе игрока в мир (если ещё не начат/не завершён). |
| **Автозавершение** | Квест закрывается сам, когда выполнены все цели. Если выключить — нужна команда `/storyquest complete`. |

## Условия, ветки и кооп

В редакторе квеста нажмите **«Условия...»**. Здесь задаются:

- **Требуемые квесты** — список квестов, которые должны быть завершены. Режим **«Все»**
  требует весь список, **«Любой»** — хотя бы один квест.
- **Скрывать, пока не выполнены условия** — если включено, квест не появляется в журнале
  до выполнения требований. Иначе он виден, но заблокирован.
- **Ветка** — квесты с одинаковым непустым именем взаимоисключающие. Ветка фиксируется
  в момент старта: после выбора одной альтернативы другие блокируются до сброса прогресса.
- **Кооп: личный / общий** — личный квест хранит прогресс игрока, общий использует
  один прогресс на весь мир.

Условия в 1.2.0 проверяются только по завершённым квестам. Требование проверяется
по прогрессу своего типа: общий квест — по общему прогрессу мира, личный — по прогрессу
игрока. Смешанные цепочки работают, но редактор показывает предупреждение.

После завершения квеста и при входе игрока игра пересчитывает доступные `autoStart`-квесты.
Циклы условий запрещены; отсутствующие квесты разрешены при авторской работе, но
подсвечиваются предупреждением. Для тестирования можно обойти условия командой
`/storyquest force-start <quest>`.

### Общие квесты

Общий квест активен для всех игроков мира. Любой игрок может начать его и закрыть цель;
для VISIT-цели достаточно, чтобы зону посетил один участник. Команды старта и завершения,
сообщения и диалоги выполняются для каждого игрока онлайн. Для личных наград используйте
`@s`, а не `@a`: команда и так выполняется отдельно от имени каждого игрока. Ветку выбирает
первый, кто начал квест.

Общий прогресс сбрасывается отдельно:

```
/storyquest reset-shared
/storyquest reset-shared <quest>
```

В 1.2.0 общий прогресс один на мир. Это рассчитано на одну компанию на приватном сервере;
отдельные группы (пати) появятся в 1.3.0.

## Цели

### «Посещение»

Игрок должен войти в сферу.

- `Измерение` — например `minecraft:overworld`, `minecraft:the_nether`, `mymap:city`.
- `X / Y / Z` — центр зоны.
- `Радиус` — радиус сферы в блоках.
- Кнопка **«Мои координаты»** подставляет текущую позицию и измерение.

Проверка выполняется каждые `visitCheckIntervalTicks` тиков (по умолчанию 10, т.е. 2 раза в секунду).

#### Метка цели

У каждой цели «Посещение» есть своя метка. В редакторе цели нажмите **«Настроить...»**:

- **Показывать метку** — включить/выключить метку для этой цели;
- **Иконка** — галочка, булавка или звезда;
- **Цвет** — `#RRGGBB` или один из готовых цветов;
- **Текст** — подпись на компасе (пусто — используется текст цели);
- **Луч в мире** — вертикальный столб света над точкой.

Как это выглядит в игре:

- над точкой плавает иконка выбранного цвета (видна сквозь блоки);
- из точки поднимается луч, заметный издалека;
- сверху экрана — компас: стрелка направления, название цели и расстояние;
- если цель в другом измерении, компас пишет «другой мир»;
- если игрок уже в зоне — «вы на месте».

Метки показываются для **отслеживаемого** квеста. Закрепить квест можно в журнале (`J`)
кнопкой «Отслеживать» или командой `/storyquest track <quest>`.

### «Вручную»

Закрывается командой:

```
/storyquest objective complete <quest> <номер цели>
```

Номера целей начинаются с **1** (как в редакторе).

## Команды

Все команды, кроме `journal` и `track` для себя, требуют **права оператора (уровень 2)** —
их можно использовать в командных блоках и функциях датапака.

| Команда | Назначение |
|---------|------------|
| `/storyquest journal` | Открыть журнал квестов. |
| `/storyquest editor` | Открыть редактор (только оператор). |
| `/storyquest list` | Список id и названий квестов. |
| `/storyquest start <quest> [игроки]` | Начать квест с проверкой условий. |
| `/storyquest force-start <quest> [игроки]` | Начать квест, обойдя условия (для тестирования). |
| `/storyquest complete <quest> [игроки]` | Завершить квест, выполнив команды завершения. |
| `/storyquest objective complete <quest> <номер> [игроки]` | Закрыть цель вручную. |
| `/storyquest track <quest> [игроки]` | Закрепить квест в HUD. |
| `/storyquest untrack [игроки]` | Убрать трекер. |
| `/storyquest reset [игроки]` | Сбросить личный прогресс квестов. |
| `/storyquest reset-shared [quest]` | Сбросить общий прогресс мира (весь или один квест). |
| `/storyquest export [имя]` | Экспортировать все квесты в JSON. |
| `/storyquest import <имя> [merge\|replace] [confirm]` | Импортировать квесты из JSON. |
| `/storyquest dialogue <игроки> <спикер> <текст>` | Показать диалог. Страницы разделяются `|`. |

Примеры:

```
/storyquest start chapter_1_intro @a
/storyquest force-start chapter_1_intro @p
/storyquest objective complete chapter_1_intro 2 @p
/storyquest complete chapter_1_intro @p
/storyquest dialogue @p "Старейшина" "Сначала найди ключ.|Он где-то в шахте."
/storyquest export chapter_1
/storyquest import chapter_1 merge
```

## Команды в квесте (сюжетные скрипты)

В редакторе есть два поля:

- **Команды при старте** — выполняются в момент выдачи квеста;
- **Команды при завершении** — выполняются в момент завершения.

Правила:

- команды разделяются символом `;` (точка с запятой) или переводом строки;
- ведущий `/` необязателен;
- `%player%` заменяется на имя игрока;
- команды выполняются **от имени игрока**, с правами оператора, координаты источника — игрок.
  Поэтому работают `@s`, `@p`, `give`, `effect`, `summon`, `tellraw`, `function` и т.д.

Пример:

```
give @s minecraft:diamond 3; playsound minecraft:entity.player.levelup player @s; tellraw @s {"text":"Глава I завершена","color":"gold"}
```

Так можно делать ветвления сюжета через командные блоки/функции и выдавать следующий квест
командой `/storyquest start ...`.

## Диалоги

Диалог — это окно поверх игры: заголовок, имя рассказчика и текст.
Текст автоматически переносится по строкам.

- В редакторе: вкладка **«Текст»** → «Диалог при старте» / «Диалог при завершении».
- Страницы разделяются символом `|`.
- `Рассказчик` — имя в верхней части окна; можно оставить пустым.
- Закрыть/листать: кнопки, `Пробел`, `Enter`, клик мышью, `Esc`.

Команда `/storyquest dialogue` позволяет показывать диалоги из командных блоков вне квестов.

## Экспорт и импорт JSON

JSON — формат обмена, а не основное хранилище. Экспортируются только определения квестов,
прогресс игроков не переносится.

- Папка: `config/storyquest/quests/`.
- `/storyquest export` — создать файл с датой и временем в имени.
- `/storyquest export <имя>` — экспорт в `config/storyquest/quests/<имя>.json`.
- `/storyquest import <имя>` — импорт в режиме `merge`: квесты с тем же ID заменяются,
  новые добавляются, остальные остаются.
- `/storyquest import <имя> replace confirm` — полностью заменить набор квестов.
  Без `confirm` замена не выполняется.

Импорт сначала проверяет весь файл: ID, дубликаты, ссылки, циклы условий, типы целей,
цвета и координаты. При ошибке данные мира не меняются. После импорта игроки получают
новое состояние, а `autoStart`-квесты пересчитываются.

Перед импортом и сохранением в редакторе автоматически создаётся копия
`storyquest_quests.dat` в `config/storyquest/backups/`. Хранятся последние 20 копий.

Пример структуры:

```json
{
  "formatVersion": 1,
  "modVersion": "1.2.0",
  "quests": [
    {
      "id": "guard_path",
      "title": "Путь стражи",
      "requiredQuests": ["choice"],
      "requireAll": true,
      "hideUntilAvailable": false,
      "branch": "side",
      "scope": "shared",
      "objectives": []
    }
  ]
}
```

## Где хранятся данные

- **Квесты:** `world/data/storyquest_quests.dat` (внутри сохранения мира).
- **Общий прогресс коопа:** `world/data/storyquest_shared_progress.dat`.
- **Личный прогресс игроков:** в NBT игрока, в секции `PlayerPersisted`
  (переживает смерть и респавн).
- **JSON для обмена:** `config/storyquest/quests/`; резервные копии DAT:
  `config/storyquest/backups/`.

Чтобы перенести квесты на другую карту, используйте JSON-экспорт и импорт. Можно также
скопировать файл мира целиком или перенести `data/storyquest_quests.dat` в `data` другого мира.

> Перед крупным редактированием делайте резервную копию мира.

## Настройки

### Сервер / общие

`config/storyquest-common.toml`:

- `visitCheckIntervalTicks` — частота проверки зон;
- `showChatMessages` — сообщения о квестах в чат;
- `playSounds` — звуки;
- `allowManualStartFromJournal` — разрешать брать квесты из журнала.

### Клиент

`config/storyquest-client.toml`:

- `showHud`, `hudAnchor`, `hudOffsetX/Y`, `hudScale`;
- `hudMaxObjectives`, `hudBackgroundOpacity`;
- `waypointsEnabled`, `waypointCompass`, `waypointCompassOffsetX/Y` — метки и компас;
- `waypointBeams`, `waypointBeamHeight`, `waypointMaxDistance`, `waypointIconScale` — вид меток;
- `theme` — тема интерфейса: `PAPER` (пергамент, по умолчанию) или `BOOK`
  (кожаный переплёт). Старые ключи `accentColor` и `panelColor` больше не используются.

Все настройки доступны в игре: **Mods → StoryQuest → Config**.

## Ограничения текущей версии

- Один активный трекер в HUD (несколько квестов могут быть активны одновременно).
- Метки и компас показываются только для отслеживаемого квеста.
- Нет деревьев диалогов с выборами — ветвление делается условиями и командами.
  Ветвящиеся диалоги запланированы на 1.4.0.
- Нет проверки предметов/убийств как отдельных типов целей: для этого используйте команды
  и `/storyquest objective complete`.
- Кооп в 1.2.0 — один общий прогресс на мир. Отдельные группы (пати) появятся в 1.4.0.
  Команды общего квеста выполняются для всех игроков онлайн, поэтому награды получают
  только те, кто был в сети в момент старта или завершения.
- Экспорт и импорт доступны командами; кнопок в редакторе пока нет.
- Редактор доступен только операторам; игроки видят журнал и диалоги.
